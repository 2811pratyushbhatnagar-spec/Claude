# Substantial-Result Checklist — DRAFT v0.1 · NOT FROZEN

> **This is a draft. Freezing it is Pratyush's signature alone — a system that sets its own
> success bar is self-sealing.** Until frozen, this checklist informs evidence packets but
> certifies nothing.

## Pre-registration form (written down and VERSION-FROZEN *before* destroy-attempts run)
- **Claim:** one sentence, register-tagged (exact / empirical / structural / open).
- **Falsifier:** what observation/computation/argument would kill it.
- **Destroy-standard (per result-type):** the predefined bar destroy-attempts must exhaust —
  e.g. *enumeration result:* independent re-implementation + boundary/edge sweep + definitional-
  ambiguity check; *proof:* blinded multi-auditor reconstruction + attack list + machine check of
  every countable subclaim; *null result:* the search space stated exactly, exhaustion demonstrated,
  and the strongest near-miss documented.

## The six criteria ("interesting" → "candidate substantial result" requires ALL)
1. **Clearly stated claim** (pre-registered, register-tagged).
2. **Independent reproduction** exists (different implementation or different agent, blinded).
3. **Destroy-attempts exhausted** to the pre-registered per-type standard — not "we tried some."
4. **Relationship to existing theory explicit:** extends / revises / refutes — *stated*, not "must fit."
5. **Survives repository validation** (run_checks green including regression on its numbers).
6. **Human review completed** (the Tier-3 act itself; automation never performs this step).

*Even a candidate substantial result is not a result until criterion 6. Status of this document:
DRAFT; edits by the steward; automation may propose changes as Class-B items only.*
