# Research Architecture — Four Ledgers (composability without collapse)

*The organizing result of the project: domains that interact only through explicit, evidence-backed maps and
never collapse into one another. If any one fails, the others stand. This is the reversible-contract
discipline applied to the inquiry itself — contact that preserves distinctness.*

## The principles
- **Language-first.** Before searching for privileged objects, search for the weakest formal language that
  expresses the phenomenon. Objects, invariants, and correspondences are downstream of the language. ("Prove,
  don't define," generalized: don't import rich notions — consent, promise, repair — as primitives; discover
  which ones emerge.)
- **Three success standards, never interchangeable.** Mathematics (a coherent, interesting formal theory);
  Interpretation (illuminates experience, and can be declined); Ontology (needs far stronger evidence than
  either). A win in one never counts as a win in another.
- **Interfaces, loose register.** Similar boundary patterns recur across the work (math / interpretation,
  availability / execution, structural / normative, individual / collective, P2 / P1). They appear analogous;
  no identity between them is claimed.

## Ledger A — Mathematics · *frozen v0.1 (ultracode)*
Signature, open signature decisions, weakest axioms, finite models, W-series witnesses, independence results,
proven correspondence theorems, P1 question schema.
**Success:** stands or falls independently of any interpretation.
**Status:** signature drafted; five bake-ins caught; W1–W3 verified. Next — freeze the signature, run the
witnesses, freeze the ledger.

## Ledger B — Protocol · *frozen (v0.5)*
Kernel; reversible contact / re-choosability; the self-application clauses (Transparency, Exit, Self-
application, Non-conversion, Presentation ≠ persuasion); Repair; the honest boundary.
**Success:** remains valid when applied to itself.
**Status:** frozen, closed under its own purpose — testing, not extension.

## Ledger C — Correspondence · *open (empty)*
Only statements of the form "mathematical result X corresponds structurally to protocol clause Y," each
citing evidence from *both* A and B. No bridge is drawn before both shores exist.
**Empty is an acceptable — even expected — outcome.**

## Ledger D — Ontology · *open (allowed empty indefinitely)*
P1 remains a question schema: *does there exist an object P1 and maps P1 → P2, collective(P2) → P1 such that a
meaningful closure holds?* Nothing is promoted here from A, B, or C without independent justification.
**The framework does not require an ontological completion to be a success.**

## Beyond the four ledgers

**Interpretive Journal** — a companion, not a ledger. Orientation without coercion: poetry, reflection,
metaphor, the felt readings (love, naming, silence, contact). Its rule: *an interpretive artifact may orient
attention before supplying explanation, provided it stays transparent about doing so and never substitutes
orientation for evidence.* Success standard: does the orientation illuminate experience without demanding
belief? Lives in a separate venue (e.g. Substack), explicitly labelled as exploration, borrowing none of the
ledgers' authority.

**Historical layer** — how the project's evolution stays inspectable rather than rewritten.
- *Reconciliation Notes*: dated snapshots of project state; frozen, never edited (Reconciliation 2026-07-04, …).
- *Ledger E (Evidence Log)*: append-only record of what was attempted, survived, failed, was withdrawn or
  corrected, and why. The one ledger that logs negatives — the structural guard against the project rewriting
  its own history to look inevitable.

**Six evaluation questions** — each artifact answers exactly one, judged on its own terms and borrowing
authority from none of the others. This doubles as a quick register audit: for any paragraph, ask *which
question is this trying to answer?* If the answer is "two at once," split it or explicitly mark the transition.

| Artifact | Its one question |
|---|---|
| Ledger A | What mathematical statements survive proof or reproducible computation? |
| Ledger B | Does this interaction preserve the participant's independent judgment? |
| Ledger C | Which translations are supported independently on both sides? |
| Ledger D | Which ontological questions remain meaningful after the lower ledgers stabilize? |
| Ledger E | What actually happened during the research? |
| Interpretive Journal | Does this orient attention honestly without replacing evidence? |

**Architecture freeze.** The *structure* — A / B / C / D / E + Journal — is frozen. Content versions freely
(Ledger A v0.1, Ledger B v0.5, …); the architecture versions *rarely*, and only with a reason recorded in
Ledger E. A structure that can absorb new mathematics, new protocol tests, and negative results without
reorganizing itself is the sign the framework has matured from redesign into sustained research. Ledger D
depends on nothing and nothing depends on Ledger D — so ontology can never quietly become the hidden
foundation.

## The rule that holds it together
Keep signatures separate. Keep interpretations separate. Make interfaces explicit. Allow translation only
through stated maps. **Never replace a map with an identification.** This principle survived every adversarial
pass in the project; it is already operative; and it is the strongest candidate for the work's main result —
independent of how the Layer-A mathematics develops.
